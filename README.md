# moti

> **學而時習之 不亦說乎**
> 배우고 때때로 익히면 또한 기쁘지 아니한가. — 『논어』 학이편 1

명언 앱 **motimoti**.

motimoti 는 잠깐 힘을 얻고 사라지는 동기부여가 아니라, **오래 곁에 둘 책으로 가는 입구**가 되려 한다. 명언 한 줄에서 시작해 그 문장이 나온 고전과 철학·인문학으로, 진짜 자기 계발로 나아가게 하는 것이 목표다. 그래서 연속 접속 기록·포인트·알림 같은 장치로 사람을 붙잡지 않는다 — 배움(學)과 다시 펼쳐 보는 익힘(習)이면 충분하다.

- 앱: https://sumokmax-proj.github.io/moti/

## 앱 — 명언 책을 아무 데나 펼친다

「다음」을 누르면 책을 아무 쪽이나 펼치듯 명언 한 편이 나온다. 순서도, 카테고리도, 「다 봤는지」 기록도 없다. **고르지 않는다 — 책이 고른다.** 마침 지금의 나에게 하는 말 같은 쪽을 만나는 것이 이 앱의 동기부여다.

| 기능 | 동작 |
|---|---|
| **다음** | 짧게 누르면 조용히 바뀐다(페이드) |
| **주르륵 넘기기** | 「다음」을 길게 누르거나 명언을 왼쪽으로 밀면 책장 4~7장이 넘어가다 멈춘다. 넘어가는 중에 탭하면 그 자리에서 멈춘다. 숨은 장치라 화면에 표시하지 않는다 |
| **한 장 되돌아가기** | 명언을 오른쪽으로 밀면 직전 명언이 펼쳐진다. 더 돌아갈 쪽이 없으면 책장이 살짝 들렸다 내려앉는다(반동) |
| **최근 20% 피하기** | 최근에 펼친 전체의 20%는 잠시 다시 나오지 않는다(100편이면 20편). 앱을 닫았다 열어도 기억한다 |
| **출처 쪽지** | 작가 이름을 누르면 책 사이에 끼워 둔 쪽지처럼 출처가 올라온다 — 종류와 연도(고대 저작은 「~년경」), 출처, 원문, 원전으로 가는 링크. 원문 대신 인용 자료로 확인한 7편은 「출처 확인 자료」로 밝힌다. 숨은 장치라 화면에 표시하지 않는다 |
| **판권면** | 즐겨찾기 화면 맨 아래 「이 책에 대하여」 — 책의 맨 뒤 한 쪽처럼 모토, 실린 명언과 저자 수, 시대, 원문 언어, 번역 경로와 영역자, 엮은이(Max K.), 펴낸 날을 적는다. 숫자는 앱이 데이터에서 센다 |
| **즐겨찾기** | 하트로 저장한다. 명언 문구가 나중에 고쳐져도 즐겨찾기는 지금 문구로 보인다 |
| **더 자주 펼치기** | 즐겨찾기한 명언이 두 배 자주 나온다(최근 20% 피하기는 그대로 지킨다). 즐겨찾기 화면에서 끌 수 있다 |
| **세 언어** | EN · KO · VN β. 같은 명언을 언어를 바꿔 가며 읽을 수 있다. 처음 언어는 기기 언어로 정하고(한국어 기기는 KO, 그 밖은 EN), 고르면 기억한다 |
| **공유** | 휴대폰 공유 시트, 없으면 클립보드 복사 |
| **키보드** | → 다음, Shift+→ 주르륵, ← 되돌아가기 |

화면 원칙: 박스 없는 편집 레이아웃, 명언 한 줄과 저자만. 라이트·다크 모드. 「동작 줄이기」 설정이면 넘김·반동 대신 바로 바뀐다. 375×667 에서 길이 상한을 쟀고, 더 작은 320×568 에서는 본문을 한 눈금씩 줄여 맞춘다.

### 파일

- `index.html` / `app.js` — 앱
- `quotes.js` — 명언 데이터(한국어·영어). 모든 명언은 `text` 와 `author` 에 `{ ko, en }` 을 가진다
- `quotes-vi.js` — 베트남어(베타). 명언 id 별로 붙고, 베트남어가 있는 명언만 VN 에서 나온다
- `style.css` / `tokens.css` — 확정 디자인(시안 E). 색과 간격은 전부 `tokens.css` 의 토큰이다(보관 중인 수집기도 이 파일을 읽는다)
- `.design/` — 확정안 5화면과 시안 A~G
- [QUOTE_STANDARDS.md](QUOTE_STANDARDS.md) — 명언 기준 · [PLANNING.md](PLANNING.md) — 기획과 결정 기록 · [LAUNCH_CHECKLIST.md](LAUNCH_CHECKLIST.md) — 출시 점검표

## 명언 — 141편, 기준은 까다롭게

명언은 대화하며 함께 고르고, [QUOTE_STANDARDS.md](QUOTE_STANDARDS.md) 로 거른다. 핵심만:

- **진짜인가** — 그 사람이 정말 그렇게 말했다는 근거가 그 시대의 기록(책·편지·연설·당시 기사)까지 이어지고, 위치(쪽·날짜·장)를 댈 수 있어야 한다. 원문을 직접 대조하거나, 원문 위치를 짚은 믿을 만한 2차 자료로 확인한다. 오귀속 판정이 난 문장은 싣지 않는다 (예: 마리 퀴리 49 삭제)
- **혼자 서는가** — 앱은 한 줄과 저자만 보여 준다. 원전을 모르는 사람이 읽어도 뜻이 서야 한다
- **나아가게 하는가** — 일침은 괜찮지만 숙명론이나 겁만 주는 말은 뺀다
- **원문에 충실한가** — 의역하지 않는다. 짧게 쓰려고 뜻을 덜어내지 않는다(원문 충실 > 짧게 쓰기)
- **고르게** — 한 저자는 전체의 3%까지(지금 4편). 시대·지역은 가리지 않는다
- **번역 경로를 기록한다** — 원문이 영어면 그대로, 공개된 정본 영역이 있으면 번역자와 함께, 없으면 자체 번역

태그(despair, challenge 등)는 **편집용 기록**이다. 명언을 모을 때 모자란 상황을 보는 데 쓰고, 앱 화면은 쓰지 않는다.

Claude 와 대화하며 모은다. 후보를 원문에서 찾아 대조하고(`npm run verify:sources`), 10편 남짓씩 보여 주면 승인한 것만 `quotes.js` 에 싣는다. 싣는 순서와 고칠 곳(다음 id, 번역 경로 목록, 판권의 펴낸 날, `?v=`)은 [QUOTE_STANDARDS.md](QUOTE_STANDARDS.md) 「싣기」에 있다.

`collector/` 는 명언을 폼이나 JSON 으로 등록하고 승인하던 도구다. 대화로 모으는 쪽이 원문 대조까지 함께 할 수 있어 더 나았고, 10월 9일 이후로는 쓰지 않았다. 지우지 않고 보관만 한다 — **앱이나 데이터 형식이 바뀌어도 더는 맞추지 않는다.** 자세한 것은 [collector/README.md](collector/README.md).

### 길이 — 상한과 편집 원칙은 다른 것이다

**상한(한국어 100자 / 영어 200자)은 화면이 감당하는 최대치다.** 지원하는 가장 작은 기기(375×667)에서 재서 정했고, 품질과는 무관하다. 더 작은 320×568 에서는 `app.js` 의 `fitQuoteText` 가 본문을 한 눈금씩 줄여 맞춘다 — 그래서 상한만 지키면 화면이 깨지지 않는다. 15px 까지 줄여도 넘치면 거기서 멈추고 스크롤을 허용한다.

**엄선은 [QUOTE_STANDARDS.md](QUOTE_STANDARDS.md) 의 편집 원칙이 한다** — 한국어 40자 안쪽이 기본이고, 넘길 때는 이유가 있어야 한다. 숫자 하나가 두 일을 다 하려 들면 둘 다 어설퍼진다.

## 점검 도구 — `tools/`

명언을 넣거나 고친 뒤, 커밋하기 전에 돌린다. 기준값(길이 상한, 태그, 저자당 상한, 출처 종류)은 `tools/rules.js` 한 곳에 있다.

| 명령 | 하는 일 | 걸리는 시간 |
|---|---|---|
| `npm run check` | 데이터 점검 — id 중복·삭제 id 재사용·「다음 id」, 필수 필드·길이·태그, 저자당 상한, 머리 주석의 번역 경로 개수·목록, 출처({ko, en}·종류·인용 확인 목록), 판권(펴낸 날·엮은이), 베트남어(필드·길이·표기·저자 이름 일관성), 태그별 편수 | 1초, 네트워크 없음 |
| `npm run verify:sources` | 출처 원문 대조 — 기록된 `sourceUrl` 을 실제로 열어 `original` 이 있는지, `translator.enUrl` 에 `text.en` 이 있는지 본다. `-- --ids 59,63` · `-- --from 124` 로 좁힐 수 있다 | 전체 10초 남짓 |
| `npm run test:app` | 앱 동작 72항목 — 세 언어·두 화면 크기에서 전체 명언 그리기, 최근 20% 피하기, 주르륵 넘김, 되돌아가기·반동, 즐겨찾기, 더 자주 펼치기, 화면 안정(글자 크기·가로 밀림), 베트남어, 출처 쪽지(열고 닫기·모든 명언의 내용과 링크·작은 화면), 판권면(끌어내리기 포함), 페이지 오류 | 30초 남짓 |
| `npm test` | `check` + `test:app` | |

`test:app` 은 Playwright 를 쓴다. 처음 한 번 `npm install` 이 필요하다(전역에 깔려 있으면 `NODE_PATH=$(npm root -g)` 로도 된다). 하나라도 실패하면 종료 코드 1.

## 배포

`main` 이나 `staging` 에 푸시하면 GitHub Actions(`.github/workflows/pages.yml`)가 두 브랜치를 한 사이트로 묶어 Pages 에 올린다.

| 브랜치 | 주소 | 용도 |
|---|---|---|
| `main` | https://sumokmax-proj.github.io/moti/ | 본 앱 |
| `staging` | https://sumokmax-proj.github.io/moti/staging/ | 실험 기능을 아이폰에서 미리 써 보는 곳. 로고 옆에 STG, 검색 제외(noindex), 저장 키에 `stg-` 를 붙여 본 앱의 즐겨찾기와 섞이지 않는다 |

흐름: `staging` 에서 만들어 써 보고, 마음에 들면 `main` 에 합친다. 버리면 `staging` 을 `main` 으로 되돌린다.
저장소 Settings → Pages → Source 가 「GitHub Actions」여야 이 워크플로가 배포한다.

### css/js 를 고쳤으면 `?v=` 를 올린다

`index.html` 이 로컬 css/js 를 `?v=날짜` 로 불러온다. Pages 가 이 파일들을 10분간 캐시하기 때문에, 값을 올리지 않으면 돌아온 사람의 브라우저가 **새 HTML 과 옛 js 를 섞어 쓴다.** 실제로 한 번 겪었다 — 「전체 명언」 탭이 배지 0, 빈 목록, 오류 메시지도 없이 조용히 비어 있었다.

`?v=` 를 올리면 URL 이 바뀌어 캐시가 무효가 된다. **`quotes.js` 에도 붙어 있으므로 명언을 등재한 뒤에도 올려야 한다.** 안 올리면 새 명언이 최대 10분간 안 보인다.
